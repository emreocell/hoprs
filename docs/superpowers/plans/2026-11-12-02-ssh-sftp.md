# Plano 2: SSH + SFTP — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Conectar num servidor OpenSSH de verdade: crate `hoprs-ssh` (conexão, known_hosts, autenticação agent/chave/senha/keyboard-interactive, keepalive, reconexão com backoff, canal PTY) e `SftpFs` (implementação de `RemoteFs` com pipelining), validados contra OpenSSH em Docker e ligados ao motor de transferências do Plano 1.

**Architecture:** `hoprs-ssh` expõe `SshSession`, um handle clonável dono de uma task que mantém a conexão `russh` viva, publica o estado por `watch` e reconecta sozinho. `SftpFs` (em `hoprs-remote`) pede canais à sessão: um canal SFTP para metadados e um pool de canais para streams. Quando a sessão reconecta, ele percebe pela "geração" da sessão e reabre os canais. O app (Plano 5) liga o estado da sessão a `TransferEngine::pause_site`/`resume_site`. Neste plano, essa ligação é feita num teste de ponta a ponta e documentada.

**Tech Stack:** russh 0.65 (cliente; inclui `russh::keys`), russh-sftp 3.0, secrecy 0.10, zeroize 1, sha2 0.10 + base64 0.22 (fingerprint e hosts com hash no known_hosts), hmac 0.12 (hosts com hash), tokio, async-trait. Integração: Docker Compose com Debian bookworm + openssh-server.

**Spec:** [`docs/superpowers/specs/2026-11-11-hoprs-design.md`](../specs/2026-11-11-hoprs-design.md) §4.1, §4.3, §5 (SFTP), §7 (SSH), §11. Roadmap: [`2026-11-11-00-roadmap.md`](2026-11-11-00-roadmap.md). Pendências do Plano 1: [`2026-11-12-01-followups.md`](2026-11-12-01-followups.md).

## Global Constraints

- Grafo de dependências (spec §4.1): `hoprs-ssh` → `hoprs-core`. `hoprs-remote` → `hoprs-ssh`, `hoprs-core`. Nenhuma outra aresta nova. Nada depende de `iced`.
- Ordem de autenticação (spec §7): **ssh-agent → chave do perfil → senha → keyboard-interactive**. Sem chave no perfil, a etapa "chave" tenta `~/.ssh/id_ed25519`, `~/.ssh/id_ecdsa` e `~/.ssh/id_rsa`, nessa ordem, as que existirem.
- known_hosts: lê e escreve `~/.ssh/known_hosts` no formato OpenSSH, incluindo entradas com hash (`|1|salt|hash`) e `[host]:porta` para porta ≠ 22. Host desconhecido mostra o fingerprint **SHA256** (formato `SHA256:<base64 sem padding>`, igual ao `ssh-keygen -lf`) e pede confirmação. **Fingerprint alterado bloqueia a conexão** (`ErrorKind::HostKey`). Nunca há pergunta para esse caso.
- Keepalive SSH: padrão **30 s**, configurável. Uma queda dispara reconexão com **backoff exponencial, até 5 tentativas**. Estados: `Connecting → Connected → Reconnecting → Disconnected(reason)` (spec §4.3).
- SFTP: pipelining de **64 requisições em voo × 32 KB** por arquivo (spec §5). `stat`/`list` usam `lstat` (contrato do `RemoteFs`).
- Segredos (senha, passphrase, respostas de keyboard-interactive) só em `secrecy::SecretString`. Nenhuma mensagem de erro ou `Debug` contém segredo ou conteúdo de arquivo (spec §7).
- Testes que precisam de Docker levam `#[ignore = "needs docker: docker compose -f docker/compose.yml up -d"]`. A CI tem um job `integration` que sobe o compose e roda `cargo test --workspace --all-features -- --ignored`. O job `test` não muda.
- O contrato do `RemoteFs` em `crates/hoprs-remote/src/lib.rs` vale integralmente para o `SftpFs`.
- Código, identificadores e mensagens em inglês. `cargo fmt --all --check` e `cargo clippy --workspace --all-targets --all-features -- -D warnings` limpos em todo commit. Windows fora do escopo da CI por enquanto. O código continua portável (nada de APIs só de Linux fora dos testes).

## Review Focus

1. **Arquivos especiais na listagem remota** (symlink, FIFO, socket, device): symlink aparece como `EntryKind::Symlink`. FIFO, socket e devices **não aparecem** em `list`, e `stat` neles retorna `ErrorKind::Io` ("Not a regular file"). Nunca podem travar uma leitura. → teste em Task 7.
2. **Chave do servidor trocada entre reconexões** (servidor reinstalado com a sessão aberta): a reconexão falha com `HostKey`, o estado vai para `Disconnected`, e a chave nova nunca é aceita em silêncio. → teste em Task 5.
3. **Conexão pendurada sem RST** (cabo puxado, `docker pause`): o keepalive detecta e o estado vai para `Reconnecting` em ≤ `keepalive_interval × keepalive_max` + 1 s. → teste em Task 5.
4. **Disco cheio ou quota no servidor durante a escrita**: o item termina `Failed` com `ErrorKind::Io`, sem pausar o site, porque não é falha de rede. O próximo item do site continua. → teste em Task 9.
5. **Usuário cancela um prompt** (senha, passphrase, keyboard-interactive ou host desconhecido): a conexão termina com `ErrorKind::Auth` ou `HostKey` e a mensagem `"Cancelled by user"`. Não há loop de prompts nem tentativa infinita. → testes em Tasks 3 e 4.

### Task 2: `known_hosts`

**Files:**
- Create: `crates/hoprs-ssh/src/known_hosts.rs`, `crates/hoprs-ssh/tests/fixtures/known_hosts` (entradas de teste, inclusive uma com hash gerada com `ssh-keygen -H`)

**Interfaces:**
- Consumes: `russh::keys::PublicKey` (re-export do `ssh-key`).
- Produces:
  - `pub fn fingerprint(key: &PublicKey) -> String` → `"SHA256:…"` (base64 sem padding do SHA-256 do blob do wire format, idêntico ao `ssh-keygen -lf`).
  - `pub enum HostKeyStatus { Known, Unknown, Changed { line: usize } }` (`Debug, PartialEq, Eq`)
  - `pub fn check(path: &Path, host: &str, port: u16, key: &PublicKey) -> Result<HostKeyStatus>`. Um arquivo inexistente conta como `Unknown`. O nome casa em texto puro, em lista separada por vírgula, ou com hash (`|1|base64(salt)|base64(HMAC-SHA1(salt, nome))`). O nome é `host` para a porta 22 e `[host]:port` para as outras. Uma linha que casa com o host e tem o **mesmo algoritmo** e chave diferente resulta em `Changed { line }` (1-based). Linhas de outro algoritmo não contam. Linhas `@revoked`/`@cert-authority`, comentários e linhas inválidas são ignorados.
  - `pub fn learn(path: &Path, host: &str, port: u16, key: &PublicKey) -> Result<()>` acrescenta `nome algoritmo base64` em texto puro, cria o arquivo e o diretório pai (diretório com modo `0o700` e arquivo com `0o600` no Unix) e garante a quebra de linha antes da entrada nova.
  - `pub fn remove(path: &Path, host: &str, port: u16) -> Result<usize>` apaga as linhas que casam com o host, inclusive as com hash, e retorna quantas apagou. É o gancho para "remover a entrada explicitamente" (spec §7).
  - Erros de I/O viram `hoprs_core::Error` (`From<io::Error>`).

### Task 5: Estado da sessão, keepalive e reconexão

**Files:**
- Modify: `crates/hoprs-ssh/src/session.rs`
- Create: `crates/hoprs-ssh/tests/reconnect.rs`
- Modify: `docker/compose.yml` se precisar (os testes controlam o contêiner via `docker` CLI)

**Interfaces:**
- Produces:
  - `#[derive(Clone, Debug, PartialEq)] pub enum SessionState { Connecting, Connected, Reconnecting { attempt: u32 }, Disconnected(Error) }`
  - `pub fn SshSession::state(&self) -> watch::Receiver<SessionState>`
  - `pub fn SshSession::generation(&self) -> u64`: começa em 1 e sobe a cada reconexão bem-sucedida.
  - `pub async fn SshSession::open_channel(&self) -> Result<russh::Channel<russh::client::Msg>>`: abre um canal `session` na conexão atual. Em `Reconnecting` ou `Disconnected` retorna `Network`, "Not connected", sem esperar.
  - `pub async fn SshSession::reconnect_now(&self)`: força a tentativa imediata quando o estado é `Disconnected`. É o gancho do botão "Reconnect" da UI.
  - **Comportamento:**
    - O keepalive vem do `russh::client::Config` (`keepalive_interval`, `keepalive_max`).
    - Quando o handler sinaliza `disconnected` ou o keepalive estoura, o estado vai para `Reconnecting { attempt: 1 }`. Cada tentativa espera `policy.delays()[attempt-1]` e refaz conexão, host key e autenticação com a **mesma** config e o **mesmo** prompter. Um `Changed` aborta a tentativa.
    - **Sucesso:** `generation += 1` e o estado vai para `Connected`.
    - **Esgotou as tentativas, ou recebeu `HostKey`/`Auth`:** o estado vai para `Disconnected(último erro)`. `HostKey` e `Auth` param na hora, sem consumir as tentativas restantes.

**Interfaces:**
- Produces (`pipeline.rs`, `pub(crate)`):
  - `pub const MAX_IN_FLIGHT: usize = 64;` e `pub const CHUNK: u32 = 32 * 1024;`
  - `#[async_trait] pub trait SftpIo: Send + Sync + 'static` com `read(&self, offset: u64, len: u32) -> Result<Vec<u8>>` (vazio = EOF, curto permitido), `write(&self, offset: u64, data: Vec<u8>) -> Result<()>` e `close(&self) -> Result<()>`. A implementação real (Task 7) envolve um handle aberto do russh-sftp.
  - `pub struct PipelinedReader<T: SftpIo>`, que implementa `AsyncRead + Unpin + Send`, com `new(io: Arc<T>, offset: u64) -> Self`.
    - Mantém até `MAX_IN_FLIGHT` leituras de `CHUNK` em voo, em offsets consecutivos, e entrega os bytes **em ordem**.
    - Uma leitura curta no meio pede o restante do mesmo chunk antes de avançar.
    - Uma resposta vazia marca o EOF: descarta o que estiver em voo além dele e termina o stream.
    - Um erro é entregue como `io::Error` mapeável de volta para o `ErrorKind` original. Use o mesmo esquema do `FaultFs`: `io::Error::new(io_kind_for(kind), …)`, com o `hoprs_core::Error` original como `source` para preservar a mensagem.
  - `pub struct PipelinedWriter<T: SftpIo>`, que implementa `AsyncWrite + Unpin + Send`, com `new(io: Arc<T>, offset: u64) -> Self`.
    - Junta os bytes em blocos de `CHUNK` e despacha cada bloco como `write` sem esperar a resposta, com no máximo `MAX_IN_FLIGHT` em voo. Com o limite atingido, `poll_write` fica `Pending`.
    - O primeiro erro de qualquer escrita faz as chamadas seguintes falharem.
    - `poll_flush` espera todas as escritas em voo.
    - `poll_shutdown` despacha o resto, espera **todas** as respostas e só então chama `close`, cumprindo o contrato de que o shutdown confirma os bytes.

    - `remove_file` e `remove_dir` usam `remove`/`rmdir`.
    - `chmod` e `set_modified` usam `setstat`. O `set_modified` grava atime e mtime com o mesmo valor.
