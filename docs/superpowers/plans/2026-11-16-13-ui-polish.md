# Plan 13: UI polish — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make hoprs obvious on first sight: Phosphor Regular icons everywhere, the logo in the sidebar, collapsible and hideable sidebar sections with connection state, Settings as a tab, resizable compare panel and queue, right-click menus, and a visible drag between panes; then regenerate the README and site screenshots.

**Architecture:** All work is in `crates/hoprs-app`. Icons are glyphs of a subset Phosphor TTF loaded with the other fonts and named by a typed `Icon` enum. New state lives in `App` and is driven by messages like everything else (pure `update`, effects for I/O): a context menu model (`app/menu.rs`), a settings-tab slot beside `tabs`, saved panel heights and sidebar state in `Settings`, a drag model with a 4 px threshold. Pointer positions come from one tiny root widget that publishes press positions (`ui/pointer.rs`) and from a pointer-move subscription that runs only while a drag or a resize is in progress. Overlays (menu, drag ghost) are `stack` + `pin` layers like the existing palette overlay.

**Tech Stack:** Rust 1.99.1 (pinned), iced 0.14 (`advanced` already on; `image-without-codecs` added for the logo), the existing `png` decoder, `ttf-parser` 0.25 (already in the tree, dev-dependency only), fonttools `pyftsubset` (script only, not the build).

**Spec:** `docs/superpowers/specs/2026-11-16-ui-polish-design.md` (binding, including "Builder-check rulings" and the "Screenshots" step under Delivery).

### Rulings this plan makes (open points in the spec)

1. **Refresh (F5) does not exist today** (no key, no toolbar button; `ui/files.rs` even tests that F5 is ignored). The spec lists it in the pane menus with F5 and an icon; it is added as a small action (`FileKey::Refresh`, `PaneMsg::Refresh` → the existing `request_listing`), in the palette too, and that test is changed.
2. **Ctrl+W does not exist today** and is the shell's word-delete in a terminal. It is not added: the settings tab closes with its × , the tab menu and the palette ("Close tab"), like every other tab.
3. **Dashed borders:** iced 0.14's `Border` has no dash style. A tiny `ui/dashed.rs` widget draws 1 px dashes (4 px on, 3 px off) over its content's bounds; it serves the disabled outline button (A) and the drop target outline.
4. **Ellipsis:** iced 0.14 text has no ellipsis. Text is cut to the width it has from the font's advance (JetBrains Mono 0.6 em exact; Inter estimated at 0.56 em, the container clips as a safety net), with "…" and a tooltip only when cut.
5. **Success colour:** the palette has none. A `success` token (oklch 0.72 0.13 150) and a `disabled` token (oklch 0.48 0 0, about 3:1 on `paper`) are added.
6. **Settings tab model:** a separate slot (`App::settings_tab`), not a `Tab` variant (every `Tab` has a `site`). While it is selected `active_tab` is `None`, so every existing "active tab" path already shows no connection; closing it returns to the tab it came from.
7. **Pointer positions:** `mouse_area` gives no position on press. A root `PressTracker` widget publishes `Message::PointerPressed(Point)` before its children see the press (menus open there, drags and resizes start there); moves come from `iced::event::listen_with` only while `App::tracks_pointer()`.
8. **Logo:** iced 0.14 has `image-without-codecs` (= `iced_widget/image` + `image` 0.25 with `default-features = false` + `kamadak-exif`); `image::Handle::from_rgba(w, h, pixels)` exists in `iced_core` 0.14. The 48 px PNG is decoded by the existing `icon::decode_rgba8` (made `pub(crate)`), once, into a `LazyLock<image::Handle>`.
9. **Site shots:** the site keeps its two shots (`main`, `split`) re-captured with the new UI, `main` with a drag in progress; the README gains `menu.png`, `drag.png` and `settings.png`.
