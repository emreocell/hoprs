# Plano 8: Release 1.0.0 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** o hoprs 1.0.0 instalável no Ubuntu como pacote `.deb`, com:
- o ícone escolhido (opção 9, "h that hops");
- uma entrada no menu de aplicativos;
- publicação automática no GitHub Releases quando a tag `v1.0.0` for criada.

**Architecture:**
- **Pacote:** gerado pelo `cargo-deb` a partir de `[package.metadata.deb]` no `crates/hoprs-app/Cargo.toml`.
- **Ícones:** os PNGs nos tamanhos do tema hicolor saem do SVG versionado. Ficam commitados, com um script para regenerar.
- **Workflow:** o `release.yml` roda em tags `v*`. Ele compila em release, gera o `.deb` e o `SHA256SUMS`, e cria o Release com as notas do `CHANGELOG.md`.
- **Tag:** a criação de `v1.0.0` fica fora do plano. É uma publicação e pede confirmação do autor.

**Tech Stack:** `cargo-deb`, `rsvg-convert` (librsvg2-bin) para os PNGs, `desktop-file-validate` (desktop-file-utils), `appstreamcli` (appstream), GitHub Actions + `gh`.

**Spec:** [`docs/superpowers/specs/2026-11-11-hoprs-design.md`](../specs/2026-11-11-hoprs-design.md) §2 (plataforma Linux/Ubuntu) e §6 (Secret Service). Ícone: [`assets/2026-11-13-hoprs-icon.svg`](../specs/assets/2026-11-13-hoprs-icon.svg).

**Decisões do autor (2026-11-13):** formato `.deb`, publicação no GitHub Releases, versão 1.0.0, ícone opção 9.

## Global Constraints

- **Nomes:**
  - binário instalado: `hoprs`;
  - pacote: `hoprs`;
  - ID do app (desktop, AppStream e app id do Wayland/WM_CLASS): `io.github.engviniciusbs.hoprs`.
  - O crate continua `hoprs-app`, e o nome do binário vem de `[[bin]] name = "hoprs"`.
- **Versão `1.0.0`:** vale para todos os crates, via `version.workspace = true` com `[workspace.package] version = "1.0.0"`. `hoprs --version` imprime `hoprs 1.0.0` e sai sem abrir janela.
- **Licença `MIT OR Apache-2.0`:** os dois textos vão no pacote, em `/usr/share/doc/hoprs/`.
- **Dependências do pacote:**
  - `Depends`: o `$auto` do cargo-deb, mais as bibliotecas carregadas em tempo de execução que o `$auto` não vê. O implementador confere quais são, por exemplo `libxkbcommon0`, `libwayland-client0`, `libx11-6`, `libvulkan1` / `libegl1` (wgpu) e `libdbus-1-3` (rfd e keyring).
  - `Recommends`: `xdg-desktop-portal`, `gnome-keyring | kwalletmanager | keepassxc` (provedores do Secret Service).
  - `Suggests`: `openssh-client`.
- Nada de segredos ou caminhos da máquina do autor no pacote.
- O `.deb` precisa instalar e rodar num Ubuntu 24.04 limpo (contêiner), com o `hoprs --version` funcionando.
- `cargo fmt --all --check` e `cargo clippy --workspace --all-targets --all-features -- -D warnings` limpos.

## Review Focus

1. **Instalação num Ubuntu limpo:** `apt install ./hoprs_1.0.0-1_amd64.deb` resolve todas as dependências, e `hoprs --version` roda. Nenhuma biblioteca carregada em tempo de execução pode faltar, e o binário não pode abrir a janela por engano. → Task 3.
2. **O ícone aparece no menu e na janela:** o `.desktop` é válido, o `Icon=` resolve no tema hicolor e o `StartupWMClass` bate com o app id da janela. Sem isso, o GNOME mostra um ícone genérico e não agrupa a janela. → Tasks 1 e 2.
3. **Desinstalar remove tudo que foi instalado,** e nunca os dados do usuário (`~/.config/hoprs`, `~/.local/share/hoprs`, keyring). → Task 3.
4. **Release sem binário quebrado:** o workflow falha se a versão da tag não for a do `Cargo.toml`. Os artefatos do Release batem com o `SHA256SUMS`. → Task 4.
5. **Ícone pequeno legível:** os PNGs de 16 e 24 px são gerados direto do SVG, e o checklist confere visualmente se não ficaram borrados. → Task 1.

### Task 3: Pacote `.deb`

**Files:**
- Modify: `crates/hoprs-app/Cargo.toml` (`[package.metadata.deb]`)
- Create: `scripts/package-deb.sh`, `scripts/check-deb.sh`, `docker/deb-check/Dockerfile` (Ubuntu 24.04 limpo)

**Interfaces:**
- **`[package.metadata.deb]`:**
  - `name = "hoprs"`
  - `maintainer`: o autor do commit, lido do git no momento do build pelo script, nunca escrito no arquivo
  - `section = "net"`
  - `priority = "optional"`
  - `extended-description` em inglês
  - `depends` / `recommends` / `suggests`, conforme os Global Constraints
- **Assets do pacote:**
  - `target/release/hoprs` → `usr/bin/`
  - o `.desktop` → `usr/share/applications/`
  - o metainfo → `usr/share/metainfo/`
  - cada PNG → `usr/share/icons/hicolor/NxN/apps/io.github.engviniciusbs.hoprs.png`
  - o SVG → `usr/share/icons/hicolor/scalable/apps/io.github.engviniciusbs.hoprs.svg`
  - os dois LICENSE → `usr/share/doc/hoprs/`
- **`scripts/package-deb.sh`:**
  1. instala o `cargo-deb` se faltar, numa versão fixada;
  2. roda `cargo build --release -p hoprs-app`;
  3. roda `cargo deb -p hoprs-app --no-build`;
  4. imprime o caminho do `.deb`.
- **`scripts/check-deb.sh <deb>`:**
  1. monta o contêiner Ubuntu 24.04;
  2. roda `apt-get install -y ./hoprs_*.deb`;
  3. roda `hoprs --version`;
  4. roda `desktop-file-validate` no arquivo instalado;
  5. confere que o ícone existe em todos os tamanhos;
  6. roda `apt-get remove -y hoprs` e confere que `/usr/bin/hoprs`, os ícones e o `.desktop` sumiram.

  Ao fim, o script imprime OK/FAIL por etapa e sai com código ≠ 0 se alguma falhar.
- **Bibliotecas carregadas em tempo de execução:** o implementador roda o binário instalado no contêiner com `xvfb-run hoprs` por 3 s (o `HOPRS_PROBE_STARTUP=1` do Plano 6 serve) para descobrir bibliotecas que faltam via dlopen, e acrescenta cada uma ao `depends`.

- [ ] **Step 1: Teste (falhando).** `scripts/check-deb.sh` contra um pacote ainda inexistente falha.
- [ ] **Step 2: Implementar**, até o `check-deb.sh` passar inteiro, incluindo o probe de abertura sob `xvfb-run` no contêiner.
- [ ] **Step 3: Rodar fmt, clippy e os testes.**
- [ ] **Step 4: Commit.** `git commit -m "build: Debian package"`

### Task 4: Workflow de release

**Files:**
- Create: `.github/workflows/release.yml`, `scripts/release-notes.sh` (extrai do `CHANGELOG.md` a seção da versão)
- Modify: `.github/workflows/ci.yml` (job `package`, que roda `package-deb.sh` e `check-deb.sh` em todo PR)

**Interfaces:**
- **`release.yml`:**
  - roda em `push: tags: ['v*']`, com `permissions: contents: write`;
  - **etapas:**
    1. confere que a versão da tag, sem o `v`, é igual à de `[workspace.package]`, e falha com mensagem clara se não for;
    2. roda `scripts/package-deb.sh` e depois `scripts/check-deb.sh`;
    3. gera o `SHA256SUMS`;
    4. roda `gh release create "$TAG" hoprs_*.deb SHA256SUMS --title "hoprs $VERSION" --notes-file notes.md`, com o `notes.md` vindo de `release-notes.sh`;
  - não publica nada se qualquer etapa falhar.
- **`release-notes.sh <versão>`:** imprime só a seção `## <versão>` do `CHANGELOG.md`, sem o título. Sai com erro se a seção não existir. Tem teste em shell: um `CHANGELOG` de exemplo em diretório temporário, rodado pelo próprio `ci.yml` (`bash scripts/release-notes.sh --self-test`).
- **CI:** o job `package` fica obrigatório como os outros. Ele prova a cada PR que o `.deb` instala e roda.

- [ ] **Step 1: Teste (falhando).** `release-notes.sh --self-test` falha antes de o script existir.
- [ ] **Step 2: Implementar.** Validar o YAML com `actionlint` se estiver disponível; se não estiver, revisar à mão e registrar isso no checklist.
- [ ] **Step 3: Rodar** o `release-notes.sh 1.0.0` local e o pacote local.
