# Plan 11: the app in Brazilian Portuguese (i18n) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every user-visible string of hoprs, including hoprs's own error messages, available in English and pt-BR through Fluent catalogs, with the language picked from the OS or Settings and switched live.

**Architecture:** A new `i18n` module in `hoprs-app` owns two embedded Fluent catalogs (`i18n/en.ftl`, `i18n/pt-BR.ftl`) and a process-wide active language. `ui/strings.rs` stays the only door to text: its constants become functions that look keys up with string literals. Core crates stay i18n-free: `hoprs_core::Error` gains a stable `code` plus named `args`, which the app turns into translated text.

**Tech Stack:** Rust 1.99.1, iced 0.14, `fluent-bundle` 0.16 (`concurrent::FluentBundle`), `unic-langid` 0.9, `sys-locale` 0.3, rusqlite (transfer store).

**Spec:** `docs/superpowers/specs/2026-11-15-app-i18n-pt-br-design.md`

## Global Constraints

- `cargo fmt --all --check` and `cargo clippy --workspace --all-targets --all-features -- -D warnings` clean on every commit; `cargo test --workspace` green on every commit. Tests must pass on Linux, macOS and Windows (use `tempfile`, never literal `/tmp`).
- New dependencies: `fluent-bundle`, `unic-langid`, `sys-locale` (all MIT OR Apache-2.0), in `hoprs-app` only. Core crates gain no dependency.
- Catalog files: `crates/hoprs-app/i18n/en.ftl`, `crates/hoprs-app/i18n/pt-BR.ftl`, embedded with `include_str!`.
- Keys kebab-case derived from today's names (`NEW_SITE` → `new-site`, `site_count` → `site-count`); error keys are `error-<code>`.
- Every catalog lookup in `strings.rs` is `tr("literal-key")` or `tr_args("literal-key", …)` — never a computed key. Error codes are literals in `Error::coded(kind, "code", "English")`.
- English text in `en.ftl` is byte-for-byte today's English (existing tests keep asserting it).
- pt-BR reads naturally for Brazilian developers; keep SSH, SFTP, FTP, FTPS, terminal, workspace, upload, download, host, log, keyring, ssh-agent, hoprs in English. Sentence case in both languages. Language names in themselves: "English", "Português (Brasil)"; the system option is "System" / "Sistema".
- Fluent bundles use `set_use_isolating(false)` (no U+2068/U+2069 in rendered text).
- Nothing panics on a missing key or a formatting error: pt-BR → English → the key itself (warning logged once per key).
- Tests that check pt-BR use a `Catalog` built for pt-BR directly; they never switch the process-wide language.
- Setting key `language` in the settings file: `system` (default) | `en` | `pt-BR`; unknown values read as `system` and are kept by save.
- OS locale mapping: any locale whose language subtag is `pt` (case-insensitive, `_` or `-`, any suffix like `.UTF-8`) → pt-BR; anything else, empty, `C`, `POSIX` → English.
- pt-BR formats: decimal comma, dot thousands (`4,1 KB`, `1.000`), lower-case month abbreviations (`jan fev mar abr mai jun jul ago set out nov dez`), dates `11 nov 14:02` / `02 out 2024`. Size unit symbols identical in both languages.
- Commits: `git -c user.name="$(git log -1 --format=%an)" -c user.email="$(git log -1 --format=%ae)" commit …`, messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never change git config.

## Review Focus

1. **Fluent's own number formatting.** `{ $count }` with a numeric value is formatted by Fluent, not by `format.rs`, so `1000` would show `1000` in pt-BR instead of `1.000`. Expected: the bundle's custom formatter (`set_formatter`) groups numbers per language. Test in Task 1.
2. **A coded error whose call site misses an argument** the translation uses (or an old store row with a code but malformed args JSON). Expected: the English `message` shows, no panic, and no `{$host}` leaks to the screen. Tests in Tasks 1 and 7.
3. **Odd OS locales:** `pt_BR.UTF-8@euro`, `PT`, `pt`, `C.UTF-8`, `en`, `""`. Expected: the mapping in Global Constraints. Test in Task 2.
4. **Switching language while a modal, a palette or a tab title is open.** Expected: labels the view builds change at once; nothing stays half translated after closing and reopening it. Test in Task 2 (the app update changes language and a rendered label changes).
5. **A queue file written by 1.1 (schema v2) opened by this version**, and items whose stored skip reason is `exists` / `not newer` / `already complete`. Expected: it migrates to v3; old errors show their English message; known skip reasons are translated. Tests in Task 7.

### Task 7: Coded errors in the core, store schema v3

**Files:**
- Modify: `crates/hoprs-core/src/error.rs`, `crates/hoprs-transfer/src/store.rs`, `crates/hoprs-app/src/ui/strings.rs`, every UI site that shows an `Error`'s `message` (`ui/status.rs`, `ui/queue.rs`, `ui/files.rs`, `ui/widgets.rs`, `ui/file_actions.rs`, `ui/edits.rs`, `ui/terminal.rs`, `ui/sidebar.rs`, `app/transfers.rs`, `app/actions.rs`, … — find them with `grep -rn '\.message' crates/hoprs-app/src`, excluding `logbuf.rs` and the log panel, which stay English)

**Interfaces:**
- Produces in `hoprs-core`:
  - `Error` gains `pub code: Option<&'static str>` and `pub args: Vec<(&'static str, String)>` (both default empty in `new`; `PartialEq` still derives).
  - `pub fn coded(kind: ErrorKind, code: &'static str, message: impl Into<String>) -> Self`; `pub fn arg(mut self, name: &'static str, value: impl Into<String>) -> Self`.
- Store: schema v3 (`MIGRATION_V3`: `ALTER TABLE transfers ADD COLUMN error_code TEXT; ALTER TABLE transfers ADD COLUMN error_args TEXT;`), `SCHEMA_VERSION = 3`. Because `code` is `&'static str`, reading back maps the stored code through `fn intern_code(s: &str) -> Option<&'static str>` that leaks each distinct code once (bounded by the codes in the binary; a cache `Mutex<HashMap<String, &'static str>>`). `error_args` is a JSON object of string values; malformed JSON → no args, code kept.
- Produces in `hoprs-app`: `pub fn error(err: &hoprs_core::Error) -> String` in `strings.rs`: with a code, `tr_args_checked(&format!("error-{code}"), args)`; if the key is missing **or** formatting reports any error (e.g. a missing variable), return `err.message.clone()`. This is the single sanctioned computed key; the coverage test of Task 1 ignores it.
