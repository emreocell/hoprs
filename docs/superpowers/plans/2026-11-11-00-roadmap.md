# hoprs — Roadmap de planos

Spec: [`../specs/2026-11-11-hoprs-design.md`](../specs/2026-11-11-hoprs-design.md)

A spec é dividida em seis planos. Cada um entrega software funcional e testável por si só, e cada plano só é escrito depois que o anterior estiver pronto, porque usa as assinaturas reais dele.

| # | Plano | Entrega | Spec |
|---|---|---|---|
| 1 | [Fundação + motor de transferências](2026-11-11-01-foundation-transfer-engine.md) | Workspace Cargo, CI, `hoprs-core`, trait `RemoteFs` + `MemFs`/`LocalFs`/`FaultFs`, `hoprs-transfer` completo (fila SQLite, workers, retomada, conflitos, pastas, progresso a 10 Hz), testado sem rede | §4.1, §4.2, §4.4 (eventos), §5 (menos edição remota), §10, §11 |
| 2 | SSH + SFTP | `hoprs-ssh` (auth agent/chave/senha/keyboard-interactive, known_hosts, keepalive, PTY), `SftpFs` com pipelining, reconexão com backoff, ambiente Docker (OpenSSH) e testes de integração | §4.3, §5 (SFTP), §7 (SSH) |
| 3 | FTP + FTPS | `FtpFs` (suppaftp): pool de conexões, passivo/ativo, contorno de PASV com NAT, FTPS explícito/implícito, pinning de certificado, Docker (vsftpd, pure-ftpd) | §4.3, §5 (FTP), §7 (FTPS) |
| 4 | Vault + import | `hoprs-vault` (sites.toml, workspaces.toml, keyring, export/import Argon2id + XChaCha20-Poly1305), `hoprs-import` (FileZilla `sitemanager.xml`, relatório) | §6 |
| 5 | App: shell + arquivos + fila | `hoprs-app` iced: tema v2, barra lateral (workspaces/sites), abas, painel duplo com lista virtualizada, fila, status, estados (loading/empty/error), open workspace, diálogos de segurança | §3, §8, §10 |
| 6 | Terminal + acabamento | Aba de terminal (alacritty_terminal), edição remota (`notify`), paleta Ctrl+K, log técnico, benchmarks das metas de §9 na CI | §5 (edição remota), §8, §9 |
