# 1.3.1: workspaces as groups, refresh after transfers — design

Status: approved by the author (2026-11-16) in conversation after using 1.3.0: "1- A)
2- ok, concordo". Small change; no builder check.

## Intent

Two points from the author's first day on 1.3.0:

1. **"Open workspace" gets in the way.** The big white button under an expanded workspace
   connects every site in it and restores tabs; the author does not see himself using it and
   finds it the loudest thing in the sidebar. He still wants workspaces to group sites.
2. **A transferred file does not show up.** After an upload, download or a drag between
   panes, the destination folder keeps its old listing until he presses Refresh or leaves
   and re-enters the folder.

## Approaches

**Workspaces** (the author chose A):
- A. **Workspaces become groups.** Clicking expands/collapses the list of its sites, as
  today; each site is opened on its own like any site. The big "Open workspace" button and
  the "Close workspace" link under it go away. "Open all" (today's Open workspace: connect
  all, restore tabs) stays reachable only from the workspace's right-click menu and the
  Ctrl+K palette, so nothing the app could do is lost.
- B. Remove workspaces altogether (sidebar section, forms, saved tabs). Loses grouping.
- C. Change nothing (the ⋯ menu already hides the section).

**Refresh** (the only sensible way, approved): when a transfer item finishes successfully,
quietly re-list the destination folder in every pane that shows it.

## Design

### 1. Workspaces as groups

- The expanded workspace shows its sites and nothing else below them: no primary button,
  no "Close workspace" link.
- Right-click menu of a workspace: **Open all** (the current Open workspace behaviour,
  label changed), **Close all** when that workspace is the open one (today's Close
  workspace: saves its tabs, then closes them), **Edit**.
- The palette keeps its workspace entries, with the same wording ("Open all in
  <workspace>" or the closest existing pattern).
- Strings: new or renamed keys in both catalogs; remove keys that become unused.
- README "Using hoprs" and CHANGELOG mention the change.

### 2. Refresh after transfers

- When a queue item reaches the **Done** state, the app finds its destination folder (the
  parent of the destination path for a file item; the parent of the destination folder for
  a folder item) and its side (local or remote, and for remote, the site).
- Every file pane, in any tab, that currently shows that folder on that side (same site for
  remote) is re-listed **quietly**: like the existing quiet re-list after file operations —
  selection and scroll kept where the names still exist, no loading flash, and an automatic
  compare is not re-triggered by it (Plan 12 rule R3 applies).
- **Batching:** several items finishing close together (a folder transfer, a multi-file
  drop) cause one re-list per pane, not one per file: re-list at most once per ~500 ms per
  pane, and never while that pane already has a listing in flight (re-list once more after
  it if needed).
- Failed, skipped or cancelled items do not trigger a re-list.
- Remote re-lists go through the tab's existing session (no new connection); on FTP they
  take their turn on the control connection like any listing.
- A pane that is busy with an operation, or whose site is not connected, is not re-listed.

## Non-goals

- Watching the local file system or the server for changes made outside hoprs.
- Removing the workspace data model, forms or saved tabs.

## Tests

- Workspaces: the expanded view has no Open/Close button (view helper or message-level
  check); the right-click menu offers Open all / Close all / Edit with the right enabled
  state; choosing them sends today's OpenWorkspace / CloseWorkspace.
- Refresh: a Done item whose destination folder is shown in a pane produces one quiet
  listing effect for that pane; a pane showing another folder, another site, or the other
  side gets none; Failed/Cancelled/Skipped produce none; ten items finishing together give
  one listing; a listing in flight defers the re-list; selection kept after the re-list.
